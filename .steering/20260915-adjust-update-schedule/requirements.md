# requirements.md — 株価データ更新スケジュールの見直し

## この作業でやること
`.github/workflows/update-data.yml` の自動更新スケジュールを、東証の取引時間
（前場・後場）に合わせて、15分おきに実行されるように変更する。

## 背景・前提
- 現状は平日の日本時間9〜16時台に毎時0分（1時間おき）で実行している。
- 「更新」ボタン（[[../20260913-add-refresh-button]]）はブラウザから最新の
  株価をその場で取得するものではなく、直近のActions実行で書き出された
  `data/heatmap.json` を再取得するだけ。そのため、自動更新の間隔が短いほど
  「更新」ボタンで得られるデータも新しくなる。
- 15分おきにする案について、以下のリスクを事前にユーザーへ説明し、了承済み。
  1. GitHub Actionsの実行時間・費用（publicリポジトリなら無料、privateなら
     消費が増える）
  2. yfinance（非公式のYahoo Financeスクレイピングライブラリ）へのアクセス
     頻度が上がることによるレート制限・一時ブロックのリスク増
  3. GitHub Actionsの`schedule`は「きりのいい時刻」の混雑により数分〜最大
     1時間程度遅延する場合があり、必ずしも正確に15分間隔にはならない
  4. コミット履歴が増える
- 上記を踏まえ、ユーザーは「終日15分おき」ではなく、実際の取引時間帯
  （前場9:00〜11:30、後場12:30〜15:30）に絞って15分おきにすることを希望。
  昼休み（11:30〜12:30）と場中以外の時間は対象外とし、無駄な実行を減らす。

## 受け入れ条件
1. 平日（月〜金、日本時間）のみ実行される（土日・祝日は対象外のまま。祝日は
   従来通り自動判定しない＝既存動作を維持）。
2. 日本時間 9:00〜11:30 の間、15分おき（9:00, 9:15, ... 11:30）に実行される。
3. 日本時間 12:30〜15:30 の間、15分おき（12:30, 12:45, ... 15:30）に実行される。
4. 日本時間 11:30〜12:30（昼休み）と、9:00より前・15:30より後は対象外。
5. `workflow_dispatch`（手動トリガー）は従来通り残す。
6. 取得・コミット処理（`fetch_prices.py` 実行、差分があればコミット＆push）の
   ロジック自体は変更しない。

## 制約事項
- GitHub Actionsの`cron`はUTC基準のため、日本時間との変換（JST = UTC+9）を
  YAML内のコメントで明記し、後から見て分かるようにする。
- 実行時刻の完全な正確性（GitHub側の混雑による遅延）は保証しない。
